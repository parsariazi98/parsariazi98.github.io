Skypol: learning position from the polarization pattern of the sky.

Rayleigh scattering imprints the sun's position onto the sky's angle of polarization, and the sun's apparent path over a day is a function of latitude and longitude. Skypol learns that inverse map from polarimetric imagery. The hard part is not the regression — it is building training data that generalizes and an evaluation protocol that does not quietly leak the answer.

Overview

The full pipeline, end to end.

Step 1 – 2.1 · Simulation

Sampling observers around a site the model never sees.

Observer locations are drawn inside a geodesic triangle that surrounds the target site. The target itself is deliberately excluded from simulation, so success requires interpolating the polarization geometry to an unseen position rather than memorizing a coordinate that appeared in training.

For each sampled location, a Rayleigh simulator maps date, time, and position to angle-of-polarization and degree-of-polarization fields together with the associated solar metadata. Each day is represented by 64 samples spaced uniformly from sunrise to sunset — roughly 675 seconds apart — so the network is supervised on a complete solar arc rather than on isolated, ambiguous frames.

  • Date, time, and location in; angle- and degree-of-polarization fields plus metadata out.
  • 64 trajectory samples per day, uniform in time between sunrise and sunset.
  • The target site is held out of simulation entirely.

Step 2.2 · Sensor-faithful emulation

Closing the sensor gap without inventing data.

Simulated fields are geometrically correct and photometrically wrong. Real captures carry noise, vignetting, saturation near the zenith, and a specific sensor response that a forward model does not reproduce. Rather than adding synthetic noise, emulation borrows the texture from real measurements.

For a given simulated frame, candidate real captures are restricted to a comparable solar zenith band and ranked by angular separation θsep. The residual azimuth Δaz between the matched pair is then removed by rotating the angle-of-polarization field — flipping sign, rotating by −Δaz, and flipping back, because the angle of polarization is an orientation rather than a vector. The result is an emulated frame that carries real sensor texture with the heading the simulator asked for.

  • Match candidates by zenith band, rank by angular separation.
  • Keep the residual azimuth and apply it as a sign-aware rotation.
  • Emulated frames enter training only; they never appear in validation or test.

Model

Trajectory first, then position.

The pipeline is hierarchical rather than end-to-end: a Vision Transformer reads polarization frames and predicts the solar-elevation trajectory, and a two-stage PointTransformer regresses geolocation from that trajectory. Splitting the problem lets each stage be supervised by a quantity with a clean physical meaning.

Losses chosen to match the geometry

  • Great-circle position error. The location head emits raw xyz, normalizes to the unit sphere, and is trained with a cosine embedding loss between unit vectors. The loss angle is therefore the great-circle error itself, avoiding the distortion that a direct latitude/longitude regression introduces away from the equator.
  • Zenith head. A separate head is trained with mean-squared error on cos(zenith), which is linear in the quantity the polarization pattern actually constrains.
  • Heading as auxiliary supervision. Adding heading to the trajectory predictor reduced error in both simulation and real data — the network no longer has to infer camera orientation implicitly before it can use the polarization geometry.

Open problem

Longitude error consistently exceeds latitude error. Latitude is fixed by the solar elevation envelope, while longitude depends on when that envelope peaks — so it inherits every bit of timestamp imprecision in the capture pipeline. Current work targets that timing path directly.

In progress

  • MAML-style per-day fine-tuning.
  • Aggressive pixel-knockout augmentation for occlusion robustness.
  • A compact ViT encoder as a lighter backbone.
  • Hard-negative retraining on confusable sites.

Step 4 – 5 · Evaluation

Day-held-out splits, one shared test set.

Frames within a single day are strongly correlated: the same sky, the same haze, the same calibration. A random frame-level split therefore reports something close to interpolation accuracy. Skypol splits at the day level and orders the blocks chronologically, so the test set lies strictly in the future of the training set.

Three training regimes, one evaluation

Each regime is trained separately and scored on the identical real validation and test subsets, so the comparison isolates the effect of the synthetic data rather than the effect of the split.
